# Frozen C++17 execution and private mature validation

This implementation supports [#14](https://github.com/STAR-Ability/code-startrack-judge/issues/14), [#15](https://github.com/STAR-Ability/code-startrack-judge/issues/15), and the isolated helper integration in [#10](https://github.com/STAR-Ability/code-startrack-judge/issues/10). The [active contracts](../contracts/README.md), their [clarifications](../contracts/v0.2/clarifications.md), and the sealed [package protocol](../contracts/v0.2/package-protocol.md) govern identities, case order, checker configuration, limits, recovery, and readiness. This document describes implementation; it does not amend those contracts.

The API and workers use `SchedulerClient` over the supervisor-owned `/run/startrack/judger.sock`. The API has the scheduler token and private object reader. The dedicated judger has distinct scheduler and go-judge tokens, a persistent dispatch ledger, and an ephemeral private spool. The trusted problemtools orchestration child receives a fixed environment with no credentials and a verified package workspace. Every compiler, validator, reference solution, checker, grader, and statement converter executes through the reviewed go-judge runtime.

## Frozen capability and task execution

Public admission supports only `cpp17`, configuration `cpp17-gcc-v0.2.1`, and the measured GCC version declared in [runtime constants](../../internal/runtime/types.go). The toolchain base is an exact linux/amd64 digest. The worker image digest and built checker SHA come from the actual image, not a source-only placeholder. Compiler argv and runtime argv are server-owned; the task freezes the complete identity, source SHA, exact nanosecond/byte limits, ordered cases, and checker semantics.

The compiler receives submitted source inside its sandbox. A user execution receives only its executable and current input. Its private answer is uploaded for the checker only after user execution exits. The checker launcher creates an empty feedback directory before executing the exact mature default checker. Checker exits 42 and 43 mean AC and WA; other checker exits, signals, resource failures, or infrastructure failures mean IE. User CPU, memory, output, signal, and nonzero-exit results follow the contracted verdict mapping. The first non-AC case stops judgment; the total remains the complete frozen case count. Public CPU milliseconds are the ceiling of exact nanoseconds and the maximum over actually executed cases. Public compiler diagnostics are bounded fixed messages; original streams remain private.

The private REST client snapshots the owned finite request before validation, encoding and dispatch; projection and cleanup use that same snapshot. A caller must avoid mutation during snapshot construction. Response file-error targets are checked against the frozen cached outputs; `CollectSizeExceeded` additionally requires the matching bounded pipe collector. Only bounded booleans and pinned error types survive projection. Raw failure names, paths and messages remain discarded. The exact pinned [collector](https://github.com/criyle/go-judge/blob/e9d70a0d9a3df0c62182a6e7090d7af650a1d5f8/envexec/file_collect.go) and [result precedence](https://github.com/criyle/go-judge/blob/e9d70a0d9a3df0c62182a6e7090d7af650a1d5f8/envexec/run_single.go) can retain a size-cap fact alongside a later CPU/memory status. Finite normally exiting overflow also has a nonempty top-level error: the locked [runner status](https://github.com/criyle/go-sandbox/blob/99ea73b939bda24c55256cb7dc57be636634a056/runner/status.go) supplies exactly `Output Limit Exceeded`. A bounded marker recognizes that exact outer error only when every file error is a request-bound collector cap with the same fixed representation; `HasError` remains truthful.

Complete requested output-cap facts produce contestant OLE and compiler CE, including collector caps whose original status remains TLE/MLE. Original exit/status/CPU/wall/memory observations are unchanged. Fatal or unknown statuses, compiler launch exits 126/127, absent or inconsistent facts, mixed file failures, unrequested targets and unrelated errors retain IE precedence. Dynamic copyout error text is never parsed to excuse a nonempty error. Checker and validator output failures remain IE/failed validation, and mature tool runs keep their strict infrastructure and diagnostic-download bounds. An accepted reference's output cap fails its private technical-validation evidence; it cannot qualify a package. OLE stops before answer/checker work, and every acknowledged cached input/output still requires cleanup.

The persistent ledger reserves a fencing token before dispatch. Each `Compiling`, `Compiled`, and `Judging` progress frame requires an authenticated acknowledgement after the consumer's durable state/fence check. A rejected or missing acknowledgement stops execution. Accepted requests queue within bounded capacity. Definitive errors after dispatch retain completed case facts and produce IE; uncertain transport failures stop the attempt so lease recovery allocates a fresh counted fence. Spool or sandbox-cache cleanup failure suppresses success and latches readiness failure.

## Mature helper protocol

`RunMature` receives the whole sealed manifest and verified private files. It reserves the server-derived `problemtools:<itemId>` step under the import job's fence, separately from `exact-programs:<itemId>`. Its synchronous stdio bridge permits only these typed primitives:

| Primitive | Inputs resolved by the parent |
| --- | --- |
| `COMPILE` | Exact frozen reference or validator path and bytes; one cached compilation per program. |
| `RUN_REFERENCE` | Exact frozen reference and test ordinal; all sealed reference roles are supported. |
| `RUN_VALIDATOR` | Exact frozen validator and bounded mutation input; no answer or caller argv. |
| `CHECK_OUTPUT` | Test ordinal, bounded output, exact frozen input/answer/checker flags. |
| `GRADE` | Bounded verdict input and the exact pinned original Python default grader; no flags. |
| `STATEMENT_PDF`, `STATEMENT_HTML` | Generated English TeX, statement assets, problem metadata, and public samples only. |

C++ compilation uses the frozen compiler template. Internal Python compilation uses isolated `py_compile`; Python execution uses `-I` and the fixed interpreter. Python is an internal validation profile, not a public submission language. Native stdout, stderr, and checker feedback cross the private bridge as bounded Base64 bytes with exact CPU nanoseconds and POSIX wait status. They are never normal logs or public task DTOs.

Mature references retain the source manifest's exact CPU and wall limits, including references expected to time out. The pinned verifier independently recognizes SIGXCPU as TLE; the bridge projects a measured CPU or wall `TimeLimit` to that compatibility wait status rather than raising the frozen limit to its relaxed comparison window. This projection is not a claim about the original terminating signal. Original runtime status and exact CPU/wall facts remain separate evidence.

Statement files are a Go-generated tar stream split into contiguous bounded chunks for the REST cache. The statement child validates and extracts those chunks inside its sandbox. Hidden tests, reference sources, validators, and management credentials are absent from that view. Mature PDF/HTML conversion preserves the pinned helper flow; TeX shell escape is explicitly disabled. Native/tool failures remain actual failed validation checkpoints.

The common namespace has no `/opt/startrack/libexec` bind. The parent verifies the bridge through a root-owned opened descriptor and its built-image SHA, then copies it to the fixed `/w/problemtools-bridge.py` path only for identity and statement operations. Statement transport permits at most twelve 64 MiB chunks, at most 768 MiB including archive metadata, 512 MiB of decoded regular files, and 65,536 members. Its fixed tool profile is 120 seconds CPU, 240 seconds wall, 2 GiB memory, 8 MiB output, and 128 processes. The bounded `/w` workspace is 2 GiB with 262,144 inodes, sufficient for both chunks and decoded files; leaf/global memory accounting, maximum-size acceptance, allocation denial, and cleanup still require measured Linux evidence. Frozen user, validator, reference, compiler, and checker limits retain their contracted values.

Final evidence contains all five required parts, their actual error/warning counts, and explicit `notRun` facts for interrupted or skipped checkpoints. Aggregate counters must reconcile. A checkpoint with zero errors cannot pass unless its required mature steps actually completed. Up to 2 MiB of private diagnostics are retained on completed and failed helper execution, including post-start interruption and protocol failure. Successful validation still requires the separate exact-profile validator/reference evidence.

## Readiness and qualification

The supervisor's root-owned measurement record binds a fresh live Linux PID/start-time/boot identity, immutable worker identity, reviewed security profile, and every required measured isolation check. The consumer opens the record with `O_NOFOLLOW`, validates the opened regular file's root ownership, exact mode, single link, and size, and checks immutable root-owned ancestors. A stale record, changed instance, missing required check, or cleanup fault stops new execution. Requalification of the same live instance preserves an existing fresh qualification while probes run; a changed or failed instance invalidates it.

Toolchain qualification measures compiler/Python versions, compiles and executes a C++17 canary, and exercises checker AC/WA. Mature readiness additionally requires the original grader's AC canary, the exact root-owned bridge SHA from the built image, and an isolated installed-problemtools identity probe. `MatureReady` is separate from the public execution capability. The final credential-bearing judger and go-judge executables set and measure nondumpability after exec.

Portable race tests cover byte/fence/role boundaries, queueing, progress acknowledgement, stale instances, private statement scope, checkpoint completeness, private failure evidence, and panic/cleanup failure behavior. They do not establish Linux sandbox security. Actual final-image qualification must prove limits, network and filesystem denial, read-only bind denial including nested mounts, sibling-process credential denial, cleanup, and the full real verdict matrix. Required Linux evidence is produced by the supervised qualification harness and recorded with the built artifact; source preparation and portable tests alone cannot advertise a real execution environment.

`internal/runtime/restclient/output_error_test.go` exercises frozen target binding, exact finite error recognition, in-flight owner mutation, mixed and unrelated failures, and redacted projection through the real REST decoder. `internal/runtime/output_limits_test.go` then exercises role/precedence mapping from decoded wire responses and real adapter/session flow for contestant, compiler, checker, validator/reference and mature overflow. It verifies original measurements, early stopping and one acknowledged deletion of every allocated cache object. The full two-package Go 1.26.8 `-race` suite passed on macOS on 2026-10-08 (runtime 4.152 seconds, REST client 3.151 seconds), and both packages passed `go vet`. Independent wire and role reviews found no blockers; the role reviewer independently replayed focused runtime race tests (2.781 seconds). These checks establish portable control-flow evidence; the exact final Linux matrix remains required.

The fixed [`startrack-runtime-matrix`](../../cmd/startrack-runtime-matrix/main.go) command runs as the dedicated judger UID on linux/amd64 and accepts a bounded private stdin control containing the synthetic runtime token and actual artifact digests. It executes authored synthetic fixtures through the real typed adapter: AC, WA, CE, CPU and wall TLE, MLE, OLE, RE, a post-dispatch private-answer integrity IE, checker case/float behavior, and binary stdout. Whole mature packages exercise every checkpoint, C++ and internal Python references, all four reference roles, an invalid exit-zero validator, and an accepted reference with wrong output. It checks case stopping/order/counts, exact measurement projection, duplicate execution/helper fence refusal, acknowledged cache deletion for every session, and spool removal.
