# Service development

The owned service uses [Go 1.26.8](../../toolchain.lock.json), following [ADR 0006](../adr/0006-go-service-and-locked-build.md). Install and verify the SDK with `make toolchain`; this requires Python 3.11.8+ with safe tar extraction filtering and does not change the system Go installation. Every native command sets `GOTOOLCHAIN=local`, so a global automatic resolver cannot downgrade or replace the locked compiler. `make check` checks formatting, runs vet and race tests, and compiles the complete module. `make build` writes ignored binaries under `build/`.

Native checks also verify the exact command dependency/license closure and the canonical golden vectors with independent Node.js serialization. Install Node.js 18+ for this test-only verifier; no frontend packages are required. Changes to the runtime command dependency closure require refreshed reviewed license evidence, rather than silently accepting a new module.

`make contract-test-setup` installs the exact hash-locked schema test dependencies in an ignored local virtual environment. `make check` then validates the manifest/validation-record schemas and synthetic negative/archive fixtures using that interpreter. This test engine is excluded from the service's runtime image; schema fixture checks do not establish package execution or sandbox safety.

Start with `make run` after supplying deployment-owned settings through the environment or a trusted secret facility. The program does not source `.env`; the portable infrastructure file and application credentials are separate. Apply the complete shipped migration chain and [runtime grants](../../scripts/grant-runtime.sql) first. Startup checks checksums, role authority and effective private SQL logging policy; it refuses administrative, schema-owning, inherited or cross-service credentials. Configuration errors and startup logs use bounded codes. SIGINT/SIGTERM stop admission and drain HTTP connections and workers for up to15seconds before closing resources.

| Setting | Purpose |
|---|---|
| `JUDGE_DATABASE_URL` | PostgreSQL runtime-role URL with explicit TLS policy. `sslmode=disable` is limited to loopback development. Production across a network requires certificate verification. Never log the URL or use migration/admin credentials for the service. |
| `JUDGE_PRIVATE_STORAGE_DIR` | Absolute clean path to Judge-owned private storage; no caller-selected paths or public artifact links. |
| `BACKEND_JUDGE_TOKEN` | Independent incoming Bearer token, at least 32 printable nonwhitespace bytes. |
| `JUDGE_BACKEND_TOKEN` | Independent outgoing Bearer token, at least 32 printable nonwhitespace bytes. |
| `JUDGE_LISTEN_ADDR` | IP literal and port; default `0.0.0.0:8082` on the private service network. Local smoke tests use loopback. |
| `JUDGE_MIGRATION_DATABASE_URL` | Separately scoped migration-role connection consumed only by `judge-migrate`, never the sandbox process. |
| `JUDGE_SCHEDULER_TOKEN` | Optional independent token for the controlled judger Unix socket. It must differ from both service tokens; omitting it keeps execution unavailable. API never receives the low-level go-judge token. |
| `JUDGE_CATALOG_CURSOR_KEY` | Optional independent printable signing secret,32–1,024bytes. Preserve it across restarts so unexpired catalog cursors remain usable. Omitting it keeps catalog snapshots unavailable. |
| `JUDGE_ACQUISITION_PROXY` | Optional credential-free operator proxy for fixed-source Git acquisition. Ambient proxy/Git configuration is not inherited; callers cannot supply this setting. |

The callback target is fixed at `http://backend:8081/internal/v2/events/judge`; requests cannot supply a callback URL. Language templates, toolchains, tests, validators and checker commands come from controlled versioned runtime configuration and immutable package manifests. See [task execution](tasks.md), [callbacks](callbacks.md), [license review](license-review.md), [package adaptation](package-adaptation.md) and [imports](imports.md) for workflow evidence and operator commands.

The Linux PID1 supervisor grants graceful shutdown only after the complete normal startup qualification and final process-boundary verification. It signals the API first and allows 30 seconds for an actual exit0, while the judger, runtime and genuine recurring qualification remain alive. The existing readiness freshness bound still applies. After the API exits, the supervisor atomically revokes measurement publication and stops scheduling new qualification; an already admitted probe retains its 60 second deadline and independent 5 second cache cleanup while the runtime remains available. Remaining components then receive 10 seconds for TERM. Any required KILL, nonzero exit, real probe/read/cleanup failure, or exceeded drain deadline makes shutdown fail. Initial qualification, matrix and capacity cancellation retain abort behavior.

Runtime-init preserves its separate 5 second TERM allowance for the actual go-judge manager. It returns a fixed failure for stop-signal errors, nonzero manager exit, exceeded deadline or required KILL after consuming the actual manager `Wait`; an observed unexpected exit0 also remains fatal. Actual supervisor child `Wait` completion is separate from diagnostic EOF, so an inherited pipe cannot hide a component exit. Diagnostic settlement has its own 5 second allowance before the supervisor withdraws owned readers and records failure. Helpers, component reaping and diagnostic settlement must finish before accounting descriptors close; an unresolved owner prevents a clean result. A 120 second external container-stop budget is a candidate for later measured Linux evidence, not a qualified deployment setting.

`GET /health` returns the exact raw V0.2 health DTO. Read-only probes check schema/role/logging policy, private storage durability, live worker lifecycle, measured isolation/compiler identity and registered language profiles. Import additionally requires both qualified technical-verification helpers. An absent or failed helper keeps that capability false; queries and accepted request replay remain available according to their dependency boundaries. Current source implements these gates; passing portable tests does not qualify an image for execution. Native tests use explicit mocks and never execute submitted code or imported programs on the host. [Linux qualification](linux-sandbox.md) remains required for execution.
