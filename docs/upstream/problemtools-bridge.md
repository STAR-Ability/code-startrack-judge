# Role-separated problemtools hooks

Issue #10 integrates the exact [problemtools v1.20260907 source](https://github.com/Kattis/problemtools/tree/6010cbaa37a1612117f49566b2fff8646d53faa2), commit `6010cbaa37a1612117f49566b2fff8646d53faa2`, through the service-owned [wrapper](../../scripts/problemtools-bridge.py). This is runtime interposition, not a rewritten verifier or copied upstream source. The original upstream MIT [license](../licenses/problemtools-LICENSE), bundled templates, checker, and grader retain their attribution. The wrapper is project-owned Apache-2.0 source. The existing distribution patch remains governed by [upstream.lock.json](../../upstream.lock.json).

The wrapper replaces `SourceCode.do_compile`, `Program.run`, `problem2pdf.convert`, and `problem2html.convert` at their pinned APIs. It wraps `_build_steps` only to record actual completion of all nine upstream steps; every original step function still runs. Package prechecks, config, includes, and grader checks contribute to STRUCTURE; the other steps map to the four corresponding contract checkpoints. A fatal upstream stop retains real diagnostic counters and marks every incomplete checkpoint NOT_RUN. Zero errors in an unexecuted step do not make it pass.

Compilation and execution are synchronous private NDJSON operations to the trusted Go judger. The parent verifies the frozen job/item/fence, manifest role/path/hash, sandbox profile, and runtime identity. Python receives no executable bytes, upstream cache IDs, scheduler credentials, database credentials, or execution command templates. Compiled objects remain in the parent's cache; Python sees only an empty virtual work directory and a compile result. The hook preserves upstream POSIX wait status and CPU time conventions, including validator exit 42. Every non-accepted reference role remains available to the mature verifier; the separate exact-profile proof executes all ACCEPTED references on all sealed cases.

The outer package-view process uses bundled problemtools defaults and curated C++17/Python3 language detection. It cannot read adjacent or HOME language/configuration overrides. Only the exact installed default checker and grader are resolved as tools. BuildRun, VIVA, and Checktestdata constructors and execution methods are blocked before model loading. All native subprocess, fork, exec, spawn, socket, and ctypes loading paths are blocked in the orchestration child. This is defense in depth around trusted pinned orchestration; the reviewed mature go-judge sandbox remains the execution boundary.

The fixed sandbox `--identity` probe measures the installed distribution and generated `_version.py` value `1.20260907`, validates readonly non-group/world-writable installed files and templates, and reports the corresponding release tag `v1.20260907` and role profile. Unmapped root-owned files may have UID 65534 inside the reviewed user namespace. The host parent separately verifies the wrapper's opened file is root-owned, has protected ancestors, and matches the measured SHA-256, then copies those exact bytes privately to `/w/problemtools-bridge.py` for identity/statement operations. General program roles have no project helper mount. The upstream Python distribution is a public installed dependency in the common readonly toolchain; it contains no private package data or credentials. The source revision is bound by the frozen worker image and audited offline wheel inventory; the Python revision constant alone does not establish provenance or qualification. `MatureReady` stays false unless actual helper, grader and installed-import probes pass.

The parent supplies sealed original input by ordinal for reference execution. Input validators receive only one bounded original or mature-generated mutation input. The default checker receives one sealed case input/answer plus bounded candidate output, with canonical checker flags generated from that case. The original `support/default_grader/default_grader` script (SHA-256 `054b86e6de225d45eb63c548d058ddf326e37b7af517904ff34f89e024bae205`) runs in its own sandbox with bounded upstream group-result input and empty flags. No program receives the full package, adjacent jobs, helper credentials, or caller-selected paths.

Both complete original statement conversion functions run in a separate sandbox using fixed `--statement pdf|html` wrapper argv. Its package root is `/w/problem`, containing only the generated validation statement/assets, controlled metadata, and public samples. The parent transports these bytes as at most twelve contiguous 64 MiB tar chunks, avoiding REST file-count truncation. The child streams extraction with explicit regular-file/directory, safe-path, role-prefix, duplicate, count and size checks; no links or special entries are extracted. Decoded file data is bounded to 512 MiB and transport to 768 MiB including archive metadata. The PDF check retains the original two LuaLaTeX draft-mode invocations; the child injects explicit `-no-shell-escape` into every supported TeX engine invocation. The whole HTML conversion, including in-process plasTeX and native image/tidy calls, stays in this sandbox. The pinned template ignores parent-directory class overrides. Python and native tool stdout go to bounded private stderr while the statement child returns one JSON summary frame.

The separate fixed `--qualify-statement pdf|html` mode uses that same private view and sandbox for actual artifact qualification. It keeps the original PDF converter with PDF generation enabled, including its original Ghostscript sanitization; normal mature verification still uses drafts. PDF output is fixed to `/w/qualification.pdf`, and HTML to `/w/html/index.html`. The result adds only a structural artifact summary: kind, sorted private manifest SHA-256, file count/bytes, primary-file SHA-256/bytes, and the count of the pinned HTML template's `tex2jax_process` math spans. No artifact bytes or paths leave the child. Artifact evidence requires safe regular files, at most 4,096 files, 64 MiB per file and 256 MiB total, a complete PDF envelope or UTF-8 HTML root, and actual converter success. The original math template retains TeX for MathJax; the span count proves conversion markup, not browser rendering or a network fetch. Before any native statement tool starts, the Linux child sets and measures nondumpability so its native children cannot open the trusted parent's process-memory or result descriptors through procfs. Qualification additionally launches a fixed isolated same-UID Python child that attempts to open the parent's `environ`, `mem`, and descriptors 0/1/2 without reading any bytes. Only actual EACCES/EPERM denials count; the qualification result requires `parentProcessDenied=true`. Failure stops qualification; portable artifact-shape and canary-response fixtures do not prove real conversion or this Linux process boundary.

Frames are limited to 192 MiB; mature validator mutations and each operation output are limited to 64 MiB. The parent additionally enforces the frozen role output profile, including the narrower 8 MiB checker/validator/tool bounds. Deterministic compiler, validator, checker, reference, grader, and statement failures are technical evidence; malformed protocol, isolation, or transport failures stop orchestration without a successful terminal report. Private diagnostics are bounded and retained by the parent; no raw package data appears in public DTOs or ordinary logs.

Portable [protocol tests](../../tests/test_problemtools_bridge.py) execute only project-owned test logic and inert byte fixtures. They verify role selection, sealed inputs, path/argument rejection, virtual compilation, POSIX status, bounded frames, native traps, TeX shell-escape disabling, and incomplete-step accounting. They do not qualify Linux execution. A real acceptance run still requires the built image, the exact dependency/template/tool inventory, measured role separation and cleanup, original mature checkpoints, and the complete separate all-case program journal.

Run the mandatory portable regressions with `python3 -m unittest discover -s tests -p 'test_problemtools_bridge*.py' -v`. An additional optional static compatibility regression takes `STARTRACK_PROBLEMTOOLS_SOURCE_DIR` pointing at an owner-prepared source tree from the exact reviewed Git archive. It imports the real pinned orchestration, runs all nine original check steps, and intercepts every native role with inert RPC responses. HTML-only imports `nh3` and `colorlog` are test doubles; no imported program or statement converter executes. It explicitly reports `portableOnly=true` and cannot supply qualification evidence. This test passed on macOS/Python 3.13 with the exact cached source and available parser dependencies; Linux/Python 3.11.15 behavior remains a separate runtime qualification requirement.
