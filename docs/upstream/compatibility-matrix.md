These entries identify inspected licensing; they do not expand the four contractual baselines into a fully tested module graph.

On 2026-10-07, all four `make upstream-fetch` downloads and offline `make upstream-verify` checks succeeded on macOS: exact commit identities, expected origins, Git object integrity and component license evidence matched. Independently, all 10 local license/notice hashes and 14 recorded source metadata/binary hashes matched their pinned source objects. These checks do not certify runtime behavior. When compatibility is established, replace the unverified runtime status with actual OS/kernel/architecture/cgroup/toolchain/image digest, tested adapter version, CI or Issue evidence, date and release. A macOS source checkout is never evidence of Linux isolation. The first runtime validation must include the protocol-version/listener, secret-logging and nested-binary gates described in [dependencies](dependencies.md).

Never upgrade simply because a release is newer. Record each supported combination explicitly. Keep past combinations in release manifests with original locks and image digests so old package versions and judgments remain traceable. Supporting multiple combinations later requires an explicit compatibility owner and test coverage; there is currently no validated production combination.

The fresh acquisition test used an explicitly configured credential-free trusted proxy on macOS. Direct GitHub connectivity failed in that environment. Acquisition executes Git object reads only and does not execute package code. PostgreSQL17.10 tests and portable mocks establish persistence/control flow; neither establishes Linux sandbox safety. No candidate image digest in local build output is an official release or a qualified production profile.
